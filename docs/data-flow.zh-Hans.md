# 数据流说明

> [English](data-flow.md)

这份文档的目的是让你**自己去核对**那些隐私承诺，而不是选择相信。
下面写明了具体该读哪些文件。

## 总览

Narrative Tracker 完全在你的设备上运行。不存在开发者服务器。

```
┌─────────────────────────── 你的设备 ──────────────────────────────┐
│                                                                   │
│   自我画像 ───┐                                                   │
│   事实日志 ───┼──▶  SQLite（App 私有存储）                         │
│   分析报告 ───┘         │                                         │
│                         │  只在你点击「生成分析报告」时读取         │
│                         ▼                                         │
│                    构建 prompt                                    │
│                         │                                         │
│   API Key ──────────────┤                                         │
│   (Keychain/Keystore)   │                                         │
│                         │                                         │
└─────────────────────────┼─────────────────────────────────────────┘
                          │  HTTPS，直连
                          ▼
                 你自己配置的服务地址
                 （默认 OpenAI，也可以是
                   跑在你本机的模型）

              ── 这张图里没有任何开发者服务器 ──
```

不存在所谓「本地分析引擎」。对比是由你选择的模型完成的。
App 的职责是决定**什么内容允许进入 prompt**，以及校验返回的结果。

## 四条数据流

### 1. 写入数据 —— 完全不碰网络

```
你输入  →  校验  →  SQLite INSERT  →  结束
```

`src/database/index.ts` 里集中了 App 中所有的 SQL 语句。界面层从不直接写 SQL，
所以这一个文件就是「能被存下来的东西」的完整清单。

### 2. 生成报告 —— 唯一的对外请求

```
你点击「生成分析报告」
  → 从 SQLite 读取各版本自我画像
  → 从 SQLite 读取所选时间范围内的事实记录
  → 算出覆盖度统计（有记录的天数、各主题条数）
  → 从 Keychain / Keystore 读取 API Key
  → 构建 prompt
  → HTTPS POST 到你配置的 base URL
  → 按预期 schema 校验返回内容
  → 把报告写回 SQLite
```

去读 `src/services/index.ts` 里的 `requestAnalysis`，它是 App 中**唯一走网络**的
`fetch` 调用。prompt 由同一文件里的 `buildAnalysisPrompt` 拼装，
固定的指令部分在 `src/services/analysisPrompt.ts` —— 都是可以从头读到尾的纯文本。

> 全局搜 `fetch` 会搜到第二处，在 `src/utils/readTextFile.ts`。
> 那是**仅 Web 端**的文件读取：浏览器把用户选中的文件以 `blob:` 或 `data:` URI
> 交给页面，读这种 URI 就得用 `fetch`。它不访问任何网络，原生构建里也不存在
> ——原生走的是 `expo-file-system`（`readTextFile.native.ts`）。
> 这里主动说明，免得你搜到之后以为是藏起来的东西。

要点：

- 请求由你的设备直接发往你选择的服务商
- API Key 放在该请求的 `Authorization` 头里
- **不存在任何可以截获它的开发者服务器**
- 请求体只包含你输入过的内容，以及由此算出的统计数字

### 3. 导出与导入

```
导出：SQLite  →  JSON  →  文件  →  系统分享面板
导入：文件  →  逐字段校验  →  单个事务  →  SQLite
```

导入是**替换**语义，整体走一个事务：任何一行失败都会全部回滚，
不会出现「旧数据已删、新数据只写了一半」的状态。
校验逻辑在 `src/utils/importValidation.ts`。

### 4. 删除全部数据

```
你点击「删除所有本地数据」
  → 确认
  → DELETE FROM 所有表
  → 清除 onboarding 标记，App 回到初始自我画像流程
```

不可恢复。如果以后可能还要用，先导出。

## 网络请求清单

这个 App 能发出的请求，全部在此：

| 请求 | 目标 | 触发方式 | 内容 |
|---|---|---|---|
| AI 分析 | 设置里填的 base URL | 你手动点击 | 各版本画像、范围内的事实记录、覆盖度统计 |

这个 App **不会**发出的请求：

- ❌ 把你的数据上传到任何地方
- ❌ 遥测或统计
- ❌ 崩溃上报
- ❌ 行为追踪
- ❌ 广告 SDK
- ❌ 更新检查或授权校验
- ❌ 启动时、定时、后台的任何请求

## 如何自行验证

**读四个文件**，都不长。

1. `src/services/index.ts` —— 搜 `fetch`，走网络的只有这一处
   （另一处在 `src/utils/readTextFile.ts`，是 Web 端读 `blob:`/`data:` URI 用的，
   不碰网络，见上文说明）
2. `src/services/analysisPrompt.ts` —— 发给模型的固定指令
3. `src/database/index.ts` —— App 中所有 SQL 语句
4. `package.json` —— 依赖清单。没有统计、没有崩溃上报、没有广告 SDK

**然后在运行时确认。** 用网络代理（Charles、Proxyman、mitmproxy）对着设备抓包，
正常使用 App。在你点击「生成分析报告」之前应该看不到任何流量，
点击之后恰好只有一个请求，发往你自己设置的地址。

**或者干脆把变量消掉。** 把 provider 的 base URL 指向跑在你本机的模型
（例如 `http://localhost:11434/v1`）。那样什么都不会离开你的局域网 ——
隐私问题就不再依赖信任，而是由结构本身决定的。
